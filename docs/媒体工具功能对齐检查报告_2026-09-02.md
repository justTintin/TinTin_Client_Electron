## 三、问题根因分析

### 3.1 错误的移植策略

我之前的理解是：**"服务端化 = 只保留 API 调用，砍掉复杂 UI"**

但实际上应该是：
- **服务端**：提供 API 接口（已完成 ✅）
- **客户端**：实现完整的 UI 工作流（部分缺失 ❌）

### 3.2 具体原因

1. **对 PRD 理解偏差**
   - PRD §3.4 明确要求"媒体工具卡片导航 + 表单规格"
   - 但我误以为"服务端化"意味着可以简化客户端交互

2. **时间压力下的妥协**
   - P1/P2 排期紧张，优先保证"能跑通"而非"功能完整"
   - 导致口播配音等复杂工作流被跳过

3. **缺乏系统性对比**
   - 没有逐一对比原客户端每个页面的完整功能清单
   - 仅关注了"主要链路是否通"，忽略了细节体验

## 五、经验教训

### 5.1 正确的移植流程

1. **第一步：功能清单对比**
   - 逐页列出原客户端的所有 UI 组件和交互
   - 标记哪些是"核心工作流"，哪些是"辅助功能"

2. **第二步：服务端接口对齐**
   - 确认所有 API 端点已实现
   - 验证请求/响应格式与原客户端一致

3. **第三步：客户端 UI 完整复刻**
   - **不能简化**：原客户端有的交互，Electron 必须有
   - **可以优化**：性能/体验可以提升，但功能不能少

4. **第四步：端到端测试**
   - 模拟真实用户操作路径
   - 确保每个步骤都能顺利完成

### 5.2 本次教训

- ❌ **错误做法**：看到服务端接口通了，就认为"功能已完成"
- ✅ **正确做法**：服务端接口只是基础，客户端 UI 工作流才是用户体验的核心

- ❌ **错误做法**：为了赶进度，跳过复杂但重要的功能（如口播配音）
- ✅ **正确做法**：宁可延期，也要保证核心功能完整

#### 7.2.3 视频评价预测（✅ 已实现）

**原客户端功能**（hook_score_page.py 逐项回读实测，非推测）：
1. **视觉模型状态卡**：服务端地址 + 「测试连接」（`update_vision_model_display` / `_test_vision_model`）
2. **关键帧抽取**：`_sample_times(dur)` — 前 3 秒密集取 0.5/1.5/2.5s；`span=min(20,dur)`，`span>3.2` 时再均匀取 9 帧；过滤 `t>=dur`，空则兜底 `[0.5]`。`ffmpeg_utils.extract_frame(scale="512:-2", quality=4)`
3. **视觉模型预测**：`/llm/chat/completions` 多图输入（`temperature=0.4`），严格 JSON 输出：
   - `total` 综合分 0-100、`play_level` 量级（爆款/优质/普通/偏弱）、`golden3s` 黄金 3 秒是否合格
   - `dims` 6 维得分：吸睛力/画面冲击/悬念信息/节奏/完播预测/平台适配（取自 `video_prediction_manager.DIMENSIONS`）

#### 7.2.4 视频营销检测（✅ 已实现）

**原客户端功能**（marketing_detect_page.py 逐项回读实测，非推测）：
1. **视觉模型状态卡**：与评价预测同构（`update_vision_model_display` / `_test_vision_model`）
2. **关键帧抽取**：`_sample_times(dur)` — **全片均匀**抽 5~10 帧（与评价预测的「前 3 秒密集」不同）：
   - `dur<=0` → `[0.5]`；`n=min(10, max(5, int(dur/3.0)))`；`dur<=2.0` → `[dur/2]`；否则 `n` 帧位于 `dur*(i+0.5)/n`
3. **营销研判**：`/llm/chat/completions` 多图输入（`temperature=0.3`），严格 JSON 输出：
   - `is_marketing` 是否营销/广告/带货/引流 + `confidence` 置信度 0-100
   - `category` 推广分类：直销带货 / 品牌广告 / 软广植入 / 知识付费·教育推广 / 非营销·纯内容 / 其他
   - `product_or_brand` 涉及品牌或商品、`clues` 营销线索（画面/字幕证据）
   - `analysis` 研判分析（≤150 字）+ `suggestions` 优化/合规建议
4. **结果渲染**：`_render` — 结论行（营销红 `#e74c3c` / 非营销绿 `#2ecc71`）+ 置信度 + 分类 + 品牌 + 线索/分析/建议
5. **无历史记录**：原版检测完即展示，**不做落库**

> ⚠️ **原稿虚构项已删除**：原客户端**没有爆款拆解 / 选题生成 / 文案仿写**，
> `category` 也**不是**「美妆/数码/食品」而是上列 6 类营销属性。本工具是**检测器**而非**选题器**，
> 骨架卡文案「视频营销选题」属漂移，已校正。
