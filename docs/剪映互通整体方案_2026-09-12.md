## 0. 边界声明（先读这里）

### 本期范围：两条拉通链路

**链路一：文字模板闭环**（详见 §2~§5）

```
剪映文字模板（.textpreset 明文 / key_value.json 资源 id / 效果素材本地缓存）
  ① 提取同步 → 服务端模板库（POST /text_templates/templates，zip=template.html+meta.json）
  ② 服务端合成渲染（/montage/concat 命中 → textfx 烧制）        ← 通道现有，零改动
  ③ 客户端识别（GET 模板列表 → Step4 下拉）                     ← 通道现有，零改动
  ④ 本地合成识别 + 渲染（本期主要剩余工作）
  ⑤ 导出剪映草稿时文本挂花字效果引用（v2 导出器已实测打通）
```

**链路二：音效库 / 音乐库对齐**（2026-09-12 用户裁决纳入，可行性已实测，见 §5 补充）

```
剪映本地音频缓存（Cache/music/*.mp3 明文，实测 72 个/33MB + .beat 卡点缓存）
  ① 扫描器（ffprobe 时长/响度 + 元数据映射）
  ② 服务端对齐：/sfx/upload（PANNs 自动分类标注）、/audio/bgm/upload        ← 契约现有
  ③ 智能混剪 BGM/音效选择器识别与使用（服务端库现有通道）
```

### 概念对齐（2026-09-12 用户裁决，防止再混淆）

| 概念 | 定义 |
|---|---|
| **文字模板** | 剪映直接提供的成品模板（花字库下的花字与图标包）：花字样式+动画+装饰图标封装在一起的**原子资产**，拖入轨道直接可用。其动画**封装在花字效果资源内部**，不是独立动画素材 |
| 文本动画（独立类别） | 文本片段上叠加的入场/出场/循环动画，与转场动画、贴纸动画各自成体系。本期仅作字幕轨入场动画的**可选降级能力**，不用于文字模板 |
| 本期「渲染」的对齐口径 | 服务端合成 = textfx 按 template.html 渲染（权威）；本地合成 = 同源近似（颜色/装饰图标精确、动画近似），像素级一致方案见 §5 R3 |

### 0.0 单一数据源裁决（2026-09-13 用户裁决，最高优先级）

**剪映同步的所有模板/素材，以服务端为唯一数据源（Single Source of Truth）**：

```
剪映（本机）──「从剪映同步」（仅上传）──▶ 服务端模板库（唯一权威）──下发──▶ 客户端展示（缓存）
```

- 客户端各卡片（剪映模板/花字库/文字模板/音频…）的数据源 = **服务端接口**（GET /text_templates/templates、GET /audio/library 等），不是本地剪映目录
- 本地剪映目录扫描**只出现在「从剪映同步」弹窗**（选择要上传的类目与条目）
- 同步状态由服务端数据天然承载（在库=已同步）；删除=删服务端条目，客户端刷新即消失
- 离线时客户端展示服务端最后下发的缓存，不回退到本地扫描

### 0.1 分类字典与命名规范（强制，2026-09-12 用户裁决）

> 以**剪映顶部菜单体系为唯一术语来源**；服务端 category 与本项目代码/文档命名一律按下表对齐，新增能力先登记此表再动工。

| 剪映菜单 | 子类 | 草稿 schema 落点 | 服务端落点 | 本项目命名 | 期 |
|---|---|---|---|---|---|
| 素材（媒体） | 本地/素材库视频图片 | materials.videos / images | —（不经模板库） | 视频轨 videoTrack | 已有 |
| 音频 | 音乐/音效/配音 | materials.audios | /audio/bgm、/voice/* | BGM 轨 / 配音 voice | 已有 |
| 文本 | 总类（下含三子类） | materials.texts（type: text \| subtitle） | /text_templates、/fancy/templates | 文本 text | 本期 |
| └ 花字 | 样式+动画封装的花字效果 | content.effectStyle + materials.effects（type:'text_effect'） | fancy（`resources/fancy/templates/jy_*.json`） | 花字 fancy | 本期 |
| └ **文字模板** | 成品模板包（花字+装饰图标+动画，原子资产） | 同花字 + 装饰图标（包内 elements，存储格式 type:'sticker'） | `/text_templates` zip，id=`jy_<剪映资源id>`，category=场景词 | **文字模板 textTemplate（本期主角）** | **本期** |
| └ 智能文本 | 识别/输入生成的字幕 | text material type:'subtitle' | subtitle_srt / subtitle_srt_file | 字幕 caption | 本期 |
| 贴纸 | 独立贴纸素材 | materials.stickers（StickerSegment：resource_id/sticker_id） | — | 贴纸 sticker | **二期** |
| 特效 | 画面特效 | materials.video_effects / effects | — | 特效 effect | **二期** |
| 转场 | 片段转场 | materials.transitions | — | 转场 transition | 基础已有；动画化二期 |
| 字幕 | 由智能文本生成 | 同「智能文本」 | 同「智能文本」 | 同上 | 本期 |

**命名规则**：
1. 文档/UI/注释术语以剪映菜单名为准：文字模板、花字、字幕、贴纸、特效、转场；禁止混称（文字模板≠贴纸≠特效；花字不叫特效）。
2. **装饰图标**＝文字模板包内部的组成元素（textpreset.elements，存储格式 type:'sticker' 只是包内格式），**与剪映「贴纸」菜单类别无关**——涉及包内图标时一律写「装饰图标」。
3. **category = 类目（层级属性），tags = 场景标签（检索属性），两者分离（2026-09-12 用户裁决修正）**：好物种草/美食/穿搭/科技数码/综艺/强调/热门 是**场景标签（tag 语义，可多枚举、开放扩展）**，不是层级类目；文字模板的**类目**来自剪映原始 category_name（文字模板/热门/最新…，可随剪映更新扩展，开放集合）。正确形态：`category=文字模板`（类目）+ `tags=美食,剪映同步,source=jianying-cache`（场景+溯源标签）。**过渡态**（服务端当前把场景词放 category 并硬校验 7 值枚举）：客户端 category 填合法场景词保证入库、原始类目移入 description 留痕——已报服务端按本条调整（category 收类目开放集合 / 场景词移 tags），改后一次切齐。资产类型由 **id 前缀**承载：`jy_` = 剪映文字模板同步。
4. 草稿 schema 类目名（texts/stickers/effects/transitions/material_animations/text_templates…）保持剪映原名，不自拟。
5. 代码内部命名对照：fancy=花字、textTemplate=文字模板、caption/subtitle=字幕、transition=转场、sticker=贴纸（仅指菜单类别，二期）。

> 轨道/片段/素材字段的**唯一权威定义** = **《剪映轨道格式标准_2026-09-17》**（§1 顶层 / §2 轨道 / §3 片段 / §4 素材 / §5 文字模板三件套 / §7 合规校验）。

> **两条链路口径注记（2026-09-17 对齐收尾补，防误读）**：上表「服务端接口/本地落盘」描述的是**合成链**（素材的产生与缓存）。**导出链**（写剪映草稿）实际拉取通道是 `POST /editor/export/jianying/from-task/{taskId}`（每合成任务一份清单：`draft_content` + `assets[{rel_path, download_url, sha256}]`，见 montage-final-ipc.js `editor:exportJianyingFromTasks`），与上表资产来源是先后两段：
> 1. **from-tasks 合并流**（有服务端合成任务）：资产按清单 `download_url` **直接下载进草稿目录 `assets/`**（不经过 cacheDir）；清单内段为**服务端直传段**（本地只做窗口偏移/时长裁剪/路径绝对化，标准 §0.3 条3），其非标特征（大写 id、`duration:0` 占位、`enable_video_mask` 等标准外字段）由 `auditDraftStandardConformance` **上报不阻断**（IPC 结果 `conformance` 字段 + 主进程 warn 日志）。
> 2. **单/多视频直导流**（无服务端任务，客户端自组装）：素材**不复制**，`materials.*.path` 直接引用 cacheDir/原绝对路径（草稿目录无 `assets/`，`verifyDraftFolder` 不视为问题）。
> 服务端段格式的最终形态已定（2026-09-17 裁决 B）：**服务端不出 draft 结构、只出素材+语义清单**，draft 全部由客户端标准构造器生成——立项 P1（§3.6），过渡期维持「透传+上报」。
>
> **导出器产出轨道清单（范围权威）**：以《剪映轨道格式标准_2026-09-17》§2.3 为准——主视频/字幕/关键词花字/文字模板/花字事件/口播/音效/BGM/贴纸九类产出，特效与转场挂段不独立成轨，滤镜轨未实现（登记待做）。本表「轨道类型」列是资产视角的归类，与该清单一一对应。
>
> **golden 验收工具（2026-09-17）**：`desktop/scripts/audit-golden-draft.cjs <导出草稿目录> <golden draft_content.json>`——以剪映真机草稿（如 9月17日-电商模板，解密后明文）为基线对照轨道构成/画幅/总时长/符合性/合规五项，DIFF>0 退出码 1，可作发布门禁。首轮使用即抓出 `appendBgmTrack` 段引用悬空存量 bug（附录 H #19）。

#### 详细来源说明

##### 1. 视频轨（videoTrack）

**资产来源**：服务端合成产物
- **服务端接口**：`POST /montage/concat`
  - 请求：多片段拼接参数（clips[]、transitions[]、text_templates[] 等）
  - 响应：`{ output_url, content: { duration, tracks }, subtitle_srt, ... }`
- **本地落盘**：`<cacheDir>/montage_cache/<jobId>/outputs/<taskId>.mp4`
  - `cacheDir` = 用户设置页配置的 `local.cacheDir`（如 `D:\素材库`）
  - `jobId` = 32 位 hex 随机 ID（每次分割生成新 ID）
  - `taskId` = 服务端任务 ID
- **草稿落点**：
  - `materials.videos[]`：视频素材元数据（20 字段，含 path/duration/width/height 等）
  - `tracks[0].segments[]`：视频片段（VideoSegment，含 target_timerange/source_timerange/speed 等）
- **对齐方式**：
  - 窗口起点 = 前序任务 `content.duration` 累计 + 0.5s 间隔
  - 段时长裁剪到窗口终点：`min(窗口剩余, 素材文件时长)`
  - `source_timerange` 同步裁剪

##### 2. 字幕轨（subtitleTrack）

**资产来源**：服务端合成产物
- **服务端接口**：`POST /montage/concat` 返回 `subtitle_srt` 字段
  - 格式：标准 SRT 字幕（cue 为任务内局部时间）
- **本地落盘**：不落盘，内存解析
- **草稿落点**：
  - `materials.texts[]`：文本素材（type=subtitle，38 字段，含 content/styles/alignment 等）
  - `tracks[1].segments[]`：字幕片段（TextSegment，含 clip.transform={x:0, y:-0.8} 标准位）
- **对齐方式**：
  - `start = 窗口起点 + cue.start`
  - 字幕标准位：`clip.transform = {x:0, y:-0.8}`（屏幕下方）
  - 水平居中：`alignment=1`

##### 3. 口播轨（voiceTrack）

**资产来源**：服务端 TTS 产物
- **服务端接口**：`POST /voice/tts`
  - 请求：文本 + 音色参数
  - 响应：`{ audio_url, duration }`
- **本地落盘**：`<cacheDir>/montage_cache/<jobId>/voice/<taskId>.wav`
- **草稿落点**：
  - `materials.audios[]`：音频素材（16 字段，含 path/duration/volume 等）
  - `tracks[2].segments[]`：音频片段（AudioSegment，clip=null, hdr_settings=null）
- **对齐方式**：
  - `start = 窗口起点`
  - 时长 = wav 探测时长（ffprobe）

##### 4. BGM 轨（bgmTrack）

**资产来源**：服务端音频库
- **服务端接口**：
  - 列表：`GET /audio/library?kind=音乐`
  - 下载：`GET /audio/library/{id}/download`
- **本地落盘**：`<cacheDir>/montage_cache/bgm_ai/<filename>.mp3`
- **草稿落点**：
  - `materials.audios[]`：音频素材
  - `tracks[3].segments[]`：音频片段
- **对齐方式**：
  - 覆盖全时间轴（含间隔）：`duration = totalDurationUs`
  - 音量：默认 -8dB（可配置）

##### 5. 花字轨（fancyTrack）

**资产来源**：本地资源 + 服务端模板库
- **本地资源**：`<cacheDir>/fancy/templates/jy_*.json`（从安装包 `resources/fancy/templates/` 复制到 cacheDir）
  - 花字样式定义（颜色/描边/阴影/动画等）
  - 音效声明（sound{file, gain_db}）
- **服务端接口**：`GET /fancy/templates`（列表同步）
- **本地落盘**：`<cacheDir>/fancy/templates/`（从安装包复制到 cacheDir，不随导出落盘）
- **草稿落点**：
  - `materials.texts[]`：文本素材（type=text，金色 #FFD700）
  - `materials.effects[]`：花字效果（type=text_effect，resource_id 引用）
  - `tracks[4].segments[]`：文本片段（TextSegment，含 effectStyle 引用）
- **对齐方式**：
  - `start = 窗口起点 + ev.startUs`（关键词命中时刻）
  - 入场动画：随选（打字机/淡入等）

##### 6. 文字模板轨（tplTrack）

**资产来源**：服务端模板库
- **服务端接口**：
  - 列表：`GET /text_templates/templates`
  - 详情：`GET /text_templates/templates/{id}`
- **本地落盘**：不落盘，内存缓存
- **草稿落点**：
  - `materials.texts[]`：文本素材（type=text）
  - `materials.effects[]`：文字模板效果（type=text_effect，resource_id=jy_<剪映资源id>）
  - `tracks[5].segments[]`：文本片段（TextSegment，含 effectStyle 引用）
- **对齐方式**：
  - `start = 窗口起点 + clip.startUs`（`textTemplateClips[i]` 时间，≤窗口终点）

##### 7. 音效轨（sfxTrack）

## 5. 关键实现要点（本期）

1. **文字模板素材的明文三件套**（免解密，实测）：`key_value.json`（模板 resource_id 清单）+ `Presets/Text_V2/*.textpreset`（模板包，version=5）+ `Cache/artistEffect/<rid>/`（贴纸 PNG、动画 prefab）。三者按 `effect.resource_id` 对齐。
2. **动画封装在花字效果资源内部**（.textpreset 无 animation 字段，实测证实）——剪映按 resource_id 自解析渲染，客户端/服务端不需要（也无法）搬运动画本体。
3. **装饰图标内联**：文字模板包内装饰图标 PNG 体积小（实测 1.6~18KB），base64 内联进 template.html 即可满足服务端 zip 格式（template.html+meta.json），**不依赖 S2 资源承载扩展**。
4. **上传幂等**：同 id upsert；id 规范 `jy_<剪映资源id>` 保证与剪映资源可追溯。
5. **本地渲染方案选择**：方案A（近似）先行保底；方案B = 服务端新增**参数化渲染接口**（尺寸/帧率/时长/变量可参数化，约 0.5 天）——渲染器与缓存本就支持任意参数、产物带 alpha、与合成同源同缓存（像素级一致），无需新渲染技术。**`preview.webm`（540×960 演示预览）禁止用作方案B素材**，避免错误的像素一致预期。

```typescript
/** 草稿命名：品牌+产品型号+日期时间+分辨率+音频索引+轨道时间轴 */
function timelineDraftName(): string {
  const brand = String(sharedProductInfo.value.brand || '').trim()
  const product = String(sharedProductInfo.value.product || '').trim()
  const model = String(sharedProductInfo.value.model || '').trim()
  // 品牌+产品型号（无则兜底「混剪」）
  const bp = (brand + product + model) || '混剪'
  // 日期时间：YYYYMMDD_HHmmss
  const d = new Date()
  const ymd = d.getFullYear() + String(d.getMonth() + 1).padStart(2, '0') + String(d.getDate()).padStart(2, '0')
  const hms = String(d.getHours()).padStart(2, '0') + String(d.getMinutes()).padStart(2, '0') + String(d.getSeconds()).padStart(2, '0')
  // 分辨率（splitResolution 格式 "1080x1920"，无则兜底「未知分辨率」）
  const resolution = splitResolution.value || '未知分辨率'
  // 音频索引（多音频导出时为 _A/_B/_C，单音频为空）
  const audioPart = lastComposeTasks.value.length > 1 ? `_${String.fromCharCode(65 + lastComposeTasks.value.findIndex(t => t.id === lastComposeTasks.value[0]?.id))}` : ''
  return `${bp}_${ymd}_${hms}_${resolution}${audioPart}_轨道时间轴`
}
```

**现状**：
当前 `newTrack` 函数（L128-130）只定义了基础字段：

**问题**：
- `attribute` 恒为 0，未定义轨道属性（静音/隐藏/锁定）

**剪映轨道完整属性**（根据 pyJianYingDraft track.py）：
| 字段 | 类型 | 说明 |
|-----|------|------|
| `id` | string | 轨道唯一 ID（32 位 hex） |
| `type` | string | 轨道类型（video/audio/text/sticker/effect/filter） |
| `name` | string | 轨道名称（用户可编辑） |
| `is_default_name` | boolean | 是否使用默认名称 |
| `attribute` | number | 轨道属性位掩码（0=默认，1=静音，2=隐藏，4=锁定） |
| `flag` | number | 轨道标志（保留字段） |
| `segments` | array | 片段列表 |
| `render_index` | number | 渲染顺序（0=最底层） |

> 📌 **口径修正（2026-09-16 并入时）**：本节「`render_index` 字段（轨道渲染顺序）」与随后的 newTrack options 方案**均未实施且已否定**。经《剪映轨道格式标准_2026-09-16》§2/§3.5 核实：track 本体仅 7 字段、**不含 render_index**；`render_index` 挂在 **segment** 上，由 `draft_content_tracks_render_index(tracks)` 按轨序（第 N 条轨 → seg.render_index = N）统一赋值。`newTrack(type)` 保持无 options 形态（`name=''` + `is_default_name=true` 是标准默认值，剪映显示「未命名轨道」属正常）。

**早期整改方案（❌ 未实施且已否定——render_index 挂 segment，见上方口径修正）**：
```javascript

  const {
    name = '',
    isDefaultName = true,

    attribute,
    flag: 0,
    id: hexId(),
    is_default_name: isDefaultName,
    name,
    segments: [],
    type,
    render_index: renderIndex,

}

// 使用示例
```

#### 问题 5：视频片段之间缺少间隔（含全轨道同步）

**✅ 已实施整改**（2026-09-16）：

**核心口径：半秒间隔 = 窗口级偏移，所有轨道随窗口起点同步**——不是只改视频轨，
否则字幕/口播/BGM/模板轨会与视频错位（每过一个片段累积 0.5s 漂移）。

**常量单一口径**（jianying-exporter.js L51）——模块级导出，主进程与合并器共用：
```javascript
// 2026-09-16 用户裁决：视频片段之间添加半秒（500000 微秒）间隔，所有轨道随窗口起点同步。
// 模块级单一口径：exportMultiToDraft / mergeJianyingManifests 与 montage-final-ipc 共用
const VIDEO_GAP_US = 500000
// module.exports 导出 VIDEO_GAP_US；montage-final-ipc.js 用 JY.VIDEO_GAP_US 引用
```

**① 单视频导出（exportMultiToDraft，jianying-exporter.js）—— 逐轨覆盖清单**：

| 轨道 | 处理方式 |
|------|---------|
| 视频轨 | `cursorUs += clip.durationUs` 后加间隔（最后一个不加） |
| 口播轨（voiceTrack） | voice 段落于 `cursorUs + vc.startUs`（随片段窗口偏移自动同步） |
| 字幕轨 + 关键词轨（fancy/tpl） | 第二条 `cursorUs` 累计循环同步加间隔 |
| 文字模板轨（tplTrack） | 两条生成路径（有/无字幕）均同步加间隔 |
| BGM 轨 / 贴纸轨 | 时长参数 `totalDurationUs` 含间隔（BGM = 4s+0.5s+4s = 8.5s 覆盖全时间轴） |
| `content.duration` | 同步含间隔（草稿总时长） |

```javascript
// 总时长含间隔（探测后统一补）
totalDurationUs += clips[clips.length - 1].durationUs
if (clips.length > 1) totalDurationUs += (clips.length - 1) * VIDEO_GAP_US

// 每条轨道循环末尾（视频/字幕/模板三条循环同口径）：
cursorUs += clip.durationUs
if (i < clips.length - 1) cursorUs += VIDEO_GAP_US
```

**② 多成片合并（mergeJianyingManifests，jianying-exporter.js L515-563）**：
窗口起点（`cursorUs`）与返回 `durationUs` 均含间隔——所有轨道段（视频/字幕/音频）
在合并时统一按窗口偏移，即使后续不重排的音频轨（口播/BGM）也对齐：
```javascript
const segWindowUs = Number(content.duration) || 0
durationUs += segWindowUs
cursorUs += segWindowUs
if (mi < list.length - 1) { cursorUs += VIDEO_GAP_US; durationUs += VIDEO_GAP_US }
```

**③ 多成片导出 IPC（montage-final-ipc.js）—— 三处窗口同步**：
```javascript
// (a) 字幕重建窗口起点（trackOffsets）：accUs 累计含间隔 → 字幕随所在片段窗口对齐
if (i < manifests.length - 1) accUs += JY.VIDEO_GAP_US

// (b) 视频轨重排：视频段间加间隔（非音频轨才重排起点，仅 video 类在此叠间隔）
if (tr.type === 'video' && qi < segs.length - 1) cur += JY.VIDEO_GAP_US

// (c) 置6 模板三件套/花字/音效追加：offsetUs 窗口起点含间隔（winEnd 仍=窗口内时长）
if (i < taskIds.length - 1) offsetUs += JY.VIDEO_GAP_US
```

**测试同步更新**（jianying-exporter.test.mjs，三处断言）：

#### 问题 6：字幕显示在画面中间 + 字幕/音效时间戳错位（用户实测 2026-09-16）

导出器对「片段窗口起点」同时用了两套基准，文件时长 ≠ 成片时长时逐段累积漂移：

| 轨道组 | 窗口基准（修复前） | 实测窗口（5 任务样本） |
|--------|------------------|-------------------|
| 视频轨 | 素材文件真实时长顺序重排（probe 文件时长） | 0 / 31.5 / 63.5 / 95 / 127 s |
| 字幕/口播/BGM/模板/花字/音效 | 服务端 content.duration 累计（+半秒间隔） | 0 / 31.499 / 63.499 / 93.143 / 125.143 s |

- 任务 3：合成视频文件 31.5s vs `content.duration` 29.644s（差值 1.856s）

→ 任务 4 起视频与其余轨道错位 1.86s；草稿总时长 154.104s 与视频轨终点 158.5s 也不一致。

**✅ 已实施整改**（2026-09-16）：

**① 全轨统一「窗口口径」**（montage-final-ipc.js step 4，L1272-1318）：
