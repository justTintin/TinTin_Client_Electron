# 剪映轨道格式标准（2026-09-17 修订）

> **强制标准**（用户裁决 2026-09-16）：「剪映的轨道的所有格式的定义要形成标准，导出时根据此标准导出，而不是随便复制一个作为模板。」
> 本文是剪映草稿**轨道 / 片段 / 素材**字段的**唯一权威定义**；导出器实现必须与本文逐条对应。
> 依据来源：pyJianYingDraft 0.3.0 **全量源码**（segment.py / track.py / local_materials.py / text_segment.py / video_segment.py / audio_segment.py / effect_segment.py / animation.py / keyframe.py / script_material.py / script_file.py / template_mode.py / time_util.py / draft_folder.py / metadata/effect_meta.py）+ 本机剪映 11.5.5 实测解密草稿（9月17日-电商模板）+ key_value.json 素材分类体系 + 用户裁决。
> 变更流程（《工程规范铁律》铁律 9）：改标准 → 改导出器 → 单测钉住 → 登记《剪映互通整体方案》附录 H。

---

## 0. 总则

1. **一律按标准构造**：任何 track / segment / material 对象必须由导出器的**标准构造器**生成（见 §8 映射表）；**禁止手写段对象、禁止克隆其他草稿当模板**（2026-09-16 封面事故裁决）。
2. **最终裁判**：字段形状以本文为准；争议时以「本机剪映 11.x 实测能打开 + 轨道完整」为最终裁判。
3. **服务端只出素材+语义清单，不出 draft 结构**（2026-09-17 用户裁决 B）：from-tasks 路径中，服务端接口（`/editor/export/jianying/from-task`）的职责收敛为**素材文件（含 sha256）+ 段语义清单 + 事件表**（segments：asset 引用/入点出点/音量/归属窗口；events：文字模板与花字的命中结果+时机——命中判定在服务端，清单必须承载，否则客户端重算即成另一个双实现）；**draft_content 的 tracks/segments/materials 全部由客户端标准构造器生成**（条 1 的绝对化）。契约覆盖面（九类产出落点对照）与清单自检要求见互通方案 §3.6 P1。
   - **过渡期**（服务端契约改造完成前）：现有直传段仍按旧规则处理——本地只做「窗口偏移 + 时长裁剪 + 路径绝对化」，不重写字段；违反本标准的特征由 `auditDraftStandardConformance` 上报不阻断。
   - 裁决理由：标准唯一权威实现在客户端（构造器 + 单测 + golden 门禁），双实现必然漂移；落盘路径/多任务合并/文字模板三件套/目标剪映版本均为客户端职责。
4. **id 规范**：草稿内所有 id = **32 位小写 hex**（对照 uuid4().hex）；草稿目录名 = draft_name（命名规范见互通方案 §0.1）。
   - **例外**：剪映 11.x 实测草稿中部分 id 为**大写 UUID 带连字符**格式（如 `E1C41F84-6A64-4d0b-ADF1-A44B35252A0A`），这是剪映自身生成的格式；导出器仍统一用小写 hex。
5. **时间单位**：微秒（us）整数。`target_timerange` = 段在时间轴的位置；`source_timerange` = 段在素材文件内部的起点/时长。
6. **静默不造假**：素材/预设缺失时跳过该段（不生成占位数据）；跳过必须可排障（日志或返回值）。

### 3.2 媒体段附加字段（MediaSegment.export_json()）

来源 pyJianYingDraft `segment.py` MediaSegment，适用于视频段和音频段：

| 字段 | 类型 | 标准值 | 说明 |
|---|---|---|---|
| source_timerange | object/null | `{start: 0, duration: dur}` | 段在素材内部的起点/时长 |
| speed | float | `1.0` | 播放速度 |
| volume | float | `1.0` | 音量（有口播的素材段 `0`，见 §6） |
| extra_material_refs | array | `[speedId, …]` | 附加素材引用（speed 素材 id 必须存在，§7-⑤） |

> **volume 取值口径（2026-09-17 实测补注）**：`1.0` = 原始音量，`0` = 静音，**可以大于 1**（放大）。实测口播段 `volume = 6.098666191101074`（float32 运算残差，说明剪映内部按 float32 计算存储）。导出器仍以 `1.0` 为默认，BGM 增益等场景按计算值输出（§6）。


| 字段 | 类型 | 标准值 | 说明 |

- **字幕段**：`clip.transform = {x: 0, y: -0.8}`（`SUBTITLE_TRANSFORM_Y`；pyJianYingDraft `ClipSettings` 官方口径，单位=半画布，y 负=向下）。

## 5. 文字模板三件套（剪映原生模板引用式）

面向「零渲染保真」：由 `buildTemplateClipTrio(preset, phrase)` 从本机 `.textpreset` 机械重排生成（结构范本：王晗雨解密草稿同构实证）：

1. `materials.text_templates[]` ← preset.effect/resources/paragraphs[0].attach_info/elements（sticker）——字段清单见 §4.16。
2. `materials.texts[]` ← preset.paragraphs[0].content（仅替换 text + 对齐 range）。**关键绑定键：`texts.name = 预设 text_name`**（随机 id 时剪映回退渲染模板默认文字，2026-09-15 真机定位）。
3. 文字轨 segment ← `material_id` 指向 text_templates 实例 id；`extra_material_refs = [speed, 花字效果, 动画素材]`（按范本顺序）。

模板缺失（preset 不存在/结构不全）→ 跳过不造假；模板轨失败不阻断导出（字幕轨仍在）。

## 6. 内容时长与窗口口径

- `content.duration` = 各任务窗口累计 + 片段间半秒间隔（`VIDEO_GAP_US=500000`，最后一个不加）。
- **全轨窗口口径**（2026-09-16 用户实测定稿）：所有轨道按「任务窗口」定位，窗口 = 前序任务 content.duration 累计 + 0.5s 间隔。字幕 cue/模板/花字/音效为任务内局部系 + 窗口起点偏移。
- 有口播的素材段 `volume=0`（配音替换原声）；无口播保留原声。
