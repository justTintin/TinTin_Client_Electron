## 〇、功能概述

「仿爆款」= 给一条爆款视频（**本地视频上传**）→ **自动拆解结构**（镜头数 / 时长 / 逐镜文案 / 节奏 BPM）→ **生成复刻脚本**（保留结构、替换为本店产品文案）。右侧附带**视频编辑工作流**选择器（服务端 `output_type="video"` 的工作流），可对上传/拆解的视频做二次编辑处理。

**核心闭环（当前可用）**：`本地视频上传 → 拆解 + 复刻（flow 一条调用）→ 输出 structure + script`。
**占位环节**：生成素材（三替换）/ 组装成片 / 对比评审——原客户端为占位按钮（服务端 E-3.0 节点引擎未就绪）。

### 输入方式（2026-09-06 用户裁决）
> **下载 / 素材浏览器链路不移植**（去掉原「链接下载 + 在素材浏览器中下载」交互）。输入统一为「**本地视频上传**」：用户选择/拖入本地视频 → 客户端经通用 `window.tintin.server.upload(path, fields, onProgress)` 上传到服务端 `output/upload` 区 → 拿到 `video_path` 回填 → 走 `flow`/`analyze` 拆解。**客户端不传 `url`，不做服务端下载**。

## 二、行为源调用链（行为源 `viral_clone_client.py`）

### 2.1 来源归一化 `normalize_source(video_ref)`（V3 改动版）
> 2026-09-06 裁决：**去掉「链接→素材浏览器下载」「本地文件→素材浏览器上传入库」两条 `need_download` 分支**。本地文件一律走上传拿 `video_path`，`material_id` 作为可选的次选入参保留。

| 输入形态 | 判定 | 入参 | 备注 |
|---|---|---|---|
| 本地文件路径（`:` 前缀或 `/`、`\` 开头） | 本地文件 | **上传 → `video_path`** | **本端唯一输入**：`server.upload` 上传到 `output/upload` 区后拿 `video_path` 回填 |
| 数字 / 纯数字字符串 | `str.isdigit()` | `material_id` | 素材库 ID（可选次选） |
| 含 `/output/`、`output\`、`output/` | `_is_server_path` | `video_path` | 已上传 / 服务端 output 区路径 |
| `http(s)://` 开头 | 链接 | — | **移除**（下载链路不移植） |
| 兜底 | — | `material_id`（文本兜底） | 素材 ID 文本 |

### 2.2 端到端 `run_clone(video_ref, product_info, on_log, timeout=900)`（V3 改动版）
0. **先上传**：若 `video_ref` 为本地文件 → `server.upload` 上传到 `output/upload` 区，拿 `video_path` 回传到 `normalize_source` 后继续。
1. `normalize_source` → 若 `video_ref` 为空/无效 → `{ok:false}`。（V3 已无 `need_download` 分支）
2. 优先 `flow(product_info, **kwargs)`（一条调用，timeout=900）→ 成功返回 `{ok, structure, script, note}`。
3. `flow` 返回 `need_login`/`captcha` → 透传提示（抖音风控）。
4. `flow` 失败（旧服务端未实现）→ 回退 `analyze(**kwargs)` + `plan(structure, product_info)`。

### 2.3 直接 HTTP 封装
| 函数 | 端点 | body | 返回 |
|---|---|---|---|
| `flow` | `POST /viral/clone/flow` | `{product_info, material_id?/video_path?}` | `{ok, structure?, script?, need_login?, captcha?, error?}` |
| `analyze` | `POST /viral/clone/analyze` | `{video_path?/material_id?}` | `structure` dict |
| `plan` | `POST /viral/clone/plan` | `{structure, product_info}` | `script` dict |
| `generate` | （占位） | `{script}` | `{ok:false, reason: E30_NOT_READY}` |
| `montage` | （占位） | `{script}` | `{ok:false, reason: E30_NOT_READY}` |
| `review` | （占位） | `{video_ref}` | `{ok:false, reason: E30_NOT_READY}` |

### 2.4 动态表单提交（`_EditWorker`，右侧工作流）
- `run_workflow(workflow_id, files, values, timeout=300)` → `{ok, task_id}`。
- 轮询 `task_status(task_id, timeout=15)`，`SUCCESS/success/done/DONE/completed` 判成功；`FAILED/error` 判失败；平滑推进进度；`max_wait=1800s`（30 分钟超时）。
- `files`：本地路径（含分隔符或视频/图片/音频扩展名且 `os.path.isfile`）；`values`：素材 ID / select 值 / 文本值。

## 三、服务端契约（本地权威 `api-contract.generated.ts`）

本地生成契约 `desktop/renderer/src/types/api-contract.generated.ts` 已含 `/viral/clone/*` **七个端点**：

| 端点 | 契约说明 | 对应原客户端 |
|---|---|---|
| `POST /viral/clone/analyze` | 拆解爆款：下载(链接)/本地文件 → 镜头切分 + 逐镜视觉描述 + ASR 文案 + 节奏 → 结构 JSON | `analyze()` |
| `POST /viral/clone/plan` | 复刻规划：拆解结构 + 本店产品 → 复刻脚本（LLM 保留结构/替换产品文案） | `plan()` |
| `POST /viral/clone/flow` | 仿爆款全链：下载 → 拆解 → 复刻规划（一条调用） | `flow()` |
| `POST /viral/clone/generate` | 三替换素材生成 v1：复刻脚本 → 旁白/口播/换人/产品片段 | `generate()`（原为占位） |
| `POST /viral/clone/montage` | 复刻成片组装 v1：复刻脚本(+generate 旁白) → 素材检索+旁白/字幕/BGM → 引擎渲染 | `montage()`（原为占位） |
| `POST /viral/clone/review` | 复刻 vs 爆款对比报告：结构还原度（时长/镜头数/BPM）+ 成片多维评价 | `review()`（原为占位） |
| `POST /viral/clone/pipeline` | 替换管道串联：按定序逐步执行（前一步产物 → 下一步输入），后台任务 + poll | （无对应，本端新增可选） |

> ⚠️ **契约差异上报（铁律）**：原客户端 `viral_clone_client.py` 仅调用 `analyze/plan/flow` 三个接口，`generate/montage/review` 为**占位**（恒返回 `ok:false`，理由是"服务端 E-3.0 节点工作流引擎未就绪"）。但本地生成契约已包含这三个端点及 `pipeline`。**需在实施前与服务端核实**：这三个端点当前是否已真正可用（`generate 的 person_action/product` 契约中标注"当前缺口 → skipped + reason"，说明部分能力仍缺）。

3. **产品库加载**：复用现有产品库组合式/接口（原 `ProductLibraryManager` → 本端 `products:*` 或 `server.get('/api/product-library')`，以当前产品页实现为准）。

7. **视频上传（本端扩展，输入唯一通道）**：本地文件 → `window.tintin.server.upload('/viral/clone/upload', { file: { path } }, onProgress)` 上传到服务端 `output/upload` 区，拿 `video_path`（含 `/output/upload/` 前缀）回填。上传进度走 `onProgress` 回显。**上传端点路径需服务端确认**（契约 `/viral/clone/analyze` 的 `video_path` 指向 `server/output` 区，但当前契约无明确的视频上传端点，待服务端提供）。
