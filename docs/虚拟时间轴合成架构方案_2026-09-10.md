# 虚拟时间轴合成架构方案（智能混剪优化方向）

> 状态：方案待评审（未立项实施）
> 提出：2026-09-10，用户裁决原话「加一个透明的或者黑屏的时间轴，由分割镜头合并算出总时间。声音、视频、字幕、特效、BGM 都以此时间轴为准，而不是以视频为准」
> 关联：`docs/工程规范铁律.md`、记忆「统一合成架构：服务端优先 + 本地兜底」

## 1. 背景与动机

### 1.1 现状链路（物理合成两段式）

```
Step1 分割      服务端 /montage/split → splits/ 本地片段
Step2 确认合成  服务端 /montage/concat → outputs/montage_concat_server_*.mp4（镜头顺序物理固化）
Step3 口播配音  对 Step2 成片替换音轨 → dubbed/*.mp4（timing.json 句级时间轴锚定成片）
Step4 特效包装  对成片烧字幕/花字/文字模板 + BGM 混音 → final/*.mp4
```

> **现状口径注记（2026-09-16 用户裁决，服务端反馈）**：Step2 确认合成请求为**纯镜头拼接**——不携带任何字幕字段（burn_subtitle / font_id / fontname / subtitle_style / subtitle_srt）。依据：① 预合成阶段口播文案尚未生成（流程：预合成方案 → 确认合成 → 口播文案），无字幕数据可烧——服务端收到过「burn_subtitle=true 但无字幕内容」的空烧制请求；② 字幕/花字/文字模板烧制只发生在 Step4（SRT=口播 timing 随请求下发），Step2 若开 burn_subtitle 会与 Step4 二次烧制叠加（成片双重字幕）。代码落点：`desktop/renderer/src/composables/useVideoMontage.ts` submitConcatTask。

### 1.2 问题

- **Step2 的成片是后续所有环节的物理载体**：镜头顺序在 concat 时焊死，配音时间轴、字幕 SRT、特效坐标、剪映导出配套文件全部锚定这条成片。用户对排列的任何调整都要重新走一次服务端合成 + 下载（几十秒~分钟级）。
- **时间坐标的黑盒化**：concat 在服务端执行时长限制裁剪、出入场加速、转场，客户端拿到的只有最终成片，无法精确预知每段在成片内的真实区间。
- **失败粒度粗**：Step3/Step4 任何环节失败，退回重做也绕不开 Step2 的既有成片。

### 1.3 方向

将「视频拼接」从**物理动作**降级为**纯数据方案**：以一根**虚拟主轴（Timeline）**为唯一时间坐标系——声音、视频、字幕、特效、BGM 都是轴上的挂载项；Step2 只确认排列方案（建轴）+ 连播预览（不出片）；最终一步按轴坐标一次合成。

这正是 NLE（非线性编辑）软件与剪映草稿的内部模型：轴先于素材，画面只是轴上的一种挂载。

## 2. 目标 / 非目标

### 目标

1. 排列调整零等待：改顺序 = 改数据，不再触发服务端合成与下载
2. 全链路统一时间坐标系：配音、字幕、花字、文字模板、BGM、转场共用一根轴
3. 最终合成一次完成：拼接 + 烧制 + 混音一条 ffmpeg 链
4. 支持纯轴产物：剪映导出可选「无视频轨草稿」（纯字幕/关键词/BGM 轴，预览画布黑底）；客户端合成对未挂视频的轴区间自动黑屏（`color=black`），不产生额外实体文件
5. 可回退：服务端 concat 保留为可选快路径，出问题随时切回

### 非目标

- 不改动 Step1 分割链路（/montage/split 与 splits 落盘规则不变）
- 不追求本地复刻服务端「智能重排」算法本身——重排结果仍可由服务端给出（只排顺序，不合成），本地只负责按顺序执行拼接参数
- 不做音频时间轴编辑 UI（轴是数据结构 + 预览视图，不是剪辑器）

## 3. 核心数据结构：虚拟主轴

### 3.1 Timeline（每条待合成视频一根轴）

```typescript
/** 虚拟主轴（纯数据，可 JSON 序列化落盘；时间单位=秒，浮点） */
interface MontageTimeline {
  totalDur: number                    // 总时长 = 最后一段 end
  canvas: { width: number; height: number; fps: number }
  videoClips: Array<{                 // 视频段（挂载项，不再决定坐标）
    path: string                      // splits 片段本地路径
    sourceDur: number                 // 原始片段时长
    start: number                     // 轴上起点（计算得出）
    dur: number                       // 处理后时长（裁剪/加速后）
    speed: number                     // 生效倍速（1.0 = 无加速）
  }>
  audio: Array<{                      // 配音（按句或按镜头）
    path: string                      // wav 本地路径
    start: number
    dur: number
    clipIdx: number                   // 所属镜头序（-1 = 整轴）
  }>
  texts: Array<{                      // 字幕/花字/文字模板统一挂载
    text: string
    start: number
    dur: number
    kind: 'subtitle' | 'fancy' | 'tpl'
    style?: string                    // 样式 key（drawtext 参数由烧制端解析）
  }>
  bgm?: { path: string; gain: number; fadeIn: number; fadeOut: number }
  transitions: Array<{ afterClipIdx: number; type: string; dur: number }>  // 转场挂在「前一段」上
}
```

### 3.2 落盘

每条轴序列化为 `montage_cache/<jobId>/timeline_<n>.json`，与 `assemblePlans` 对应。重建会话时可从落盘恢复（复用 `final:listResults` 同思路）。

## 4. 坐标计算规则（本地确定性，替代服务端 concat 黑盒）

### 4.1 现有参数清单（全部有 UI，值已核实）

| 参数 | 取值 | 生效方式 |
|---|---|---|
| 时长限制 | 10/20/30/40/50 秒 | 每段裁剪到上限 |
| 转场动画 | fade(模糊)/dissolve(淡入淡出)/slideleft/slideright/slideup/slidedown/zoomin(推进)/zoomout(拉远) | 相邻段之间，挂前段 |
| 出入场加速 | 1.0/1.2/1.5/2.0/2.5/3.0 倍 | 仅作用「位置=入场/出场」的镜头（服务端 enter/exit 标注优先，命名推断兜底） |
| transition_duration | 服务端写死默认值（须在 P1 阶段实测确认具体秒数） | 转场重叠时长 |
| 输出画幅 | 服务端 source_resolution 优先 | 本地 scale/pad 统一 |
| fps/crf/preset | 服务端写死 | 本地复刻同值（P1 实测确认） |

### 4.2 计算公式

```
每段处理后时长：
  dur_i = min(sourceDur_i, 时长限制) / speed_i        （speed_i 仅入场/出场段 > 1）

转场重叠（xfade 模型，转场消耗重叠时长）：
  start_0 = 0
  start_i = start_{i-1} + dur_{i-1} − td              （td = transition_duration；相邻无转场则 td=0）
  totalDur = start_{n-1} + dur_{n-1}

xfade 链式拼接 offset（n 段、段间转场全开时）：
  offset_i（第 i 个 xfade 的时间点）= Σ(dur_0..i-1) − i × td
```

> 注意：xfade 要求两路输入分辨率/fps/像素格式一致 → 画幅与 fps 归一必须作为拼接前置（每段先 `scale+pad+fps` 归一，或统一在 concat filter 前处理）。

### 4.3 服务端行为对齐风险

本地规则是**对服务端 concat 行为的逆向假设**，P1 阶段必须用对照实验校准（见 §8）：同一组片段+参数分别走服务端 concat 与本地链，逐段比对时长（ffprobe），偏差 > 1 帧即修正规则。已知风险点：

- 服务端对「时长限制」可能是**均匀抽稀多段**而非单段硬裁剪（待实测）
- 出入场加速的加速区间可能只是头/尾若干秒而非整段（原版 edge_speedup 语义待回原客户端源码确认）
- 无转场选项时服务端是硬切还是默认 fade（待实测）

## 5. 各环节改造点

### 5.1 Step2 镜头重组（做减法）

- 「确认合成视频」→「确认排列方案」：只生成/保存 `timeline_<n>.json`，不再调 /montage/concat、不下载成片
- 预览：沿用现有连播循环预览（不看真实转场/加速，明确提示「最终效果以合成为准」）
- 服务端 /montage/concat **保留不删**，UI 加「快速合成(服务端)」入口作为回退路径

### 5.2 Step3 口播配音（改锚点）

- 配音输入从「Step2 成片」改为「splits 镜头片段 + 轴方案」：逐镜头文案独立 TTS（每镜头的文案本来独立）
- 句级 timing（timing.json）按轴坐标生成：句时间 = 镜头 start + 句内偏移
- 音轨不再预先替换进视频——wav 文件直接作为轴的 audio 挂载项，最终合成时混入

### 5.3 Step4 特效包装（合链）

- 特效烧制 + 拼接 + 混音合并为**一条 ffmpeg 链**（见 §6）
- collectCandidates() 语义变为「读轴」而非「找成片文件」；`final:listResults` 恢复逻辑改为恢复轴 JSON
- 烧制参数（字幕动画/花字/文字模板 drawtext）全部复用现有 `buildEffectBurnArgs` 体系，仅时间坐标改为轴坐标

### 5.4 剪映导出（衔接）

- 带视频草稿：视频段按轴 start/dur 排布（替代现在按成片顺序），转场用剪映原生转场 material
- **新增纯轴草稿**：不写 video 轨，只有 text + audio 轨（剪映画布黑底，无透明概念）；适合用户自行在剪映里拖画面素材
- 字幕/关键词轨时间直接用轴坐标，比现在「按成片偏移」更直接

## 6. 最终合成 ffmpeg 链设计

```
输入：轴上 n 个视频段 + m 条配音 wav + 1 条 BGM

第 1 层 归一：每段 scale=canvas:force_original_aspect_ratio=decrease,
             pad=canvas:(ow-iw)/2:(oh-ih)/2, fps=<canvas.fps>, setsar=1
第 2 层 加速：入场/出场段 setpts=PTS/speed（在归一后、拼接前；对应音频无→不处理）
第 3 层 拼接：xfade 链（transition=..., duration=td, offset=按 §4.2 公式）
             无转场相邻段用 concat filter
第 4 层 烧字：现有 drawtext 链（字幕 alpha 动画 + 花字 + 文字模板）直接接在拼接输出后，
             时间坐标已是轴坐标（烧制代码复用 buildEffectBurnArgs / buildTextFxDrawtextList）
第 5 层 混音：amix(拼接视频自带音轨[若有], 全部配音 adelay 对齐轴 start, BGM loop+afade+sidechaincompress)
             → loudnorm EBU R128 -16 LUFS（复用现有混音链）
黑屏段：某区间无视频挂载 → color=black 源垫底（lavfi color 输入，时长=黑屏区间）
```

编码参数与现有 Step4 一致（libx264 crf23 superfast 及硬件探测回退，见 montage-final-ipc/voice-tts-logic 现行实现）。

## 7. 预览方案

1. **连播预览**（Step2 现有）：按轴顺序连播片段，近似但不含转场/加速
2. **轴视图**（可选增强）：现有 textFxTracks 背景条时间轴 UI 泛化为多泳道轴视图（视频/音频/字幕/BGM 各一泳道），渲染层纯数据渲染，成本低
3. Step4 效果预览（文字模板轨）已按轴思想实现（`buildTextFxTracks`），迁移成本≈0

## 8. 一致性验证方法（P1 里程碑门槛）

| 验证项 | 方法 | 通过标准 |
|---|---|---|
| 每段时长 | 同片段集+参数，服务端 concat 与本地链各自出片，ffprobe 逐段比对（切分点用场景检测或转场帧目测） | 偏差 ≤ 1 帧 |
| 总时长 | 两版成片 ffprobe 时长差 | ≤ 0.1s |
| 转场视觉 | 同转场参数两版成片截图对比 | 人眼可接受 |
| 加速生效 | 入场/出场镜头两版播放速度对比 | 倍速一致 |
| 端到端 | 完整链（轴方案→配音→合链）出片 vs 现链路出片 | 主观验收 |
| 异常路径 | 单段/2 段/黑屏区间/无 BGM/无配音 各跑一遍 | 全部 exit 0 + moov 完整 |

## 10. 风险与回退

| 风险 | 缓解 |
|---|---|
| 本地规则与服务端行为有隐性差异（§4.3） | P1 对照实验校准；差异无法收敛的参数保留服务端执行 |
| xfade 长链性能（n 段逐对 filter） | 段数上限 20（现 UI 上限）；实测超时再分段中间落盘 |
| 一次合链失败重试代价变大 | 合链保留与现链相同的分阶段进度回调；失败可从最后成功层重试（中间产物按层落盘可选） |
| 回退需求 | 服务端 concat 全程保留；UI 灰度开关一键切回现链路 |
| 双链路并存期维护成本 | P4 完成后删除灰度开关，收敛为单链 |
