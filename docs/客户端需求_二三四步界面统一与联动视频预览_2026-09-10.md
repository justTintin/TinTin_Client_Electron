# 客户端需求：二三四步界面统一与联动视频预览

> 状态：需求已受理，待排期（未实施）
> 提出：2026-09-10，用户原话「把原来的二三四步的界面统一，右边都是视频预览，左边为执行步骤。视频预览会根据合成条数显示，视频左上角标对应条数，进行不同步时，右边位置不变，会根据左边处理，在视频显示预览效果」
> 关联：`docs/虚拟时间轴合成架构方案_2026-09-10.md`（P5 轴视图泳道与本需求的联动预览互补）

## 1. 需求背景

当前智能混剪 Step2/3/4 三步界面结构不一致：

| 步骤 | 现状布局 | 视频预览 |
|---|---|---|
| Step2 镜头重组 | 单卡纵向：参数组 → 镜头表 → 按钮区（预览嵌在卡片中部） | 有（连播预览，嵌在流程中间，位置随内容浮动） |
| Step3 口播配音 | 单卡纵向：克隆设置 → 两列表格 → 按钮区 | 无（只有音频试听） |
| Step4 特效包装 | 左 成片列表+按钮，右 视频预览（`vd4-result` 左右两栏） | 有（单块，双击成片后显示） |

问题：切步时右侧内容形态反复变化（有预览/无预览/预览位置不同），用户在「调整参数 → 看效果」循环中视线锚点不稳定；多条待合成视频没有并列可视化的进度/效果对比。

## 2. 需求详述

### R1 布局统一：左操作 + 右预览两栏

Step2/3/4 统一为固定两栏结构：

```
┌──────────────────────────────────────────────┐
│ 步骤条（现有 step-bar 不动）                    │
├───────────────────────────┬──────────────────┤
│ 左栏：执行步骤操作区         │ 右栏：视频预览区   │
│ （各步现有控件迁入，功能不变）│ （见 R2/R4）      │
└───────────────────────────┴──────────────────┘
```

- 左栏宽度、右栏宽度三步一致（右栏固定宽度，左栏自适应）
- 各步现有功能控件**全部保留**，只做位置迁移，不改交互逻辑

### R2 多条预览 + 条数角标

- 预览区按**合成条数**（Step2 生成视频数量 / Step3 配音行数 / Step4 成片数）显示对应数量的视频块，网格排列（建议 2 列，超出滚动）
- 每块视频**左上角**角标显示对应条数：`第 1 条`、`第 2 条`……（overlay 样式，半透明底）
- 块数随上一步产物数量动态生成；无产物时显示空态占位

### R3 位置不变

- 切换 Step2 → Step3 → Step4 时，右栏预览区**位置、尺寸保持不动**，仅内容刷新
- 左栏内容切换，右栏不跳动、不折叠

### R4 联动预览：右侧实时反映左侧处理

| 步骤 | 右侧每块视频显示的内容 |
|---|---|
| Step2 | 该条方案的镜头排列连播预览（现有连播逻辑按条拆分）；左栏调整排列/参数后刷新 |
| Step3 | 配音完成一条即点亮一块：播放配音后视频（dubbed 成片）；未配音的条显示原视频 + 「待配音」占位；左侧单行生成/批量进度实时对应到块 |
| Step4 | 特效预览：以候选视频为底，叠加当前特效配置的字幕/花字/文字模板效果（与左侧效果预览条同参数）；合成完成后切换为最终成片播放 |

## 3. 验收标准

1. Step2/3/4 右栏预览区四边位置逐像素一致（切步无位移）
2. 生成 3 条时右侧出现 3 块视频，角标 `第 1/2/3 条` 与成片顺序一一对应
3. Step3 某条配音完成后，对应块从「待配音」切换为可播放配音视频，无需切步
4. Step4 调整特效参数，右侧预览效果同步更新
5. 各步原有功能（镜头拖拽/配音表格/特效设置/合成导出）回归无损

## 4. 技术落点

| 改动 | 位置 |
|---|---|
| 三步统一两栏容器（新布局组件或共享 CSS 骨架） | `VideoMontage.vue`（step===1/2/3 三个 template 重排） |
| 多块预览网格 + 角标 | 新组件 `StepPreviewPane`（props: sources[], labels[], overlay） |
| 联动数据源 | Step2: assemblePlans；Step3: voiceRows(dubbedPath)；Step4: collectCandidates() + 特效参数（复用 buildTextFxTracks/buildEffectBurnArgs 同口径参数做 CSS 叠加预览） |
| 预览播放器 | 复用全局 Plyr 方案（记忆：全局视频播放器采用 Plyr） |

## 5. 待确认问题（实施前与用户对齐）

1. 多条视频网格排列：固定 2 列还是自适应？单块是否支持点击放大？
2. Step4 特效预览是「CSS 叠加模拟」（快、近似）还是「ffmpeg 实时烧制单帧」（准、慢）？
3. Step2 连播预览按条拆分后，原「单击方案查看镜头序列」交互是否保留在左栏？
4. 与「虚拟时间轴方案 P5 泳道轴视图」的关系：本需求先行，轴视图作为右栏底部的可选增强，两者不冲突。

## 6. 边界与约束

- 不改动各步业务逻辑与 IPC 链路，纯表现层重构
- UI 文案铁律不适用于本需求（本需求为客户端自提的新交互，非原版一比一移植范畴，用户已裁决）
- 布局迁移需回归三条既有门禁 + 真机验证切步锚点稳定性
