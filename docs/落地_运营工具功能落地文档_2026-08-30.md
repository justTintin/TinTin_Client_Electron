### 4.2 我的知识库（OtKnowledgeBase）

> ⏸️ **2026-09-02 用户裁决：本模块整块暂缓，不实施。**
>
> 复校结论（五路证据，详见 [媒体工具功能对齐检查报告_2026-09-02.md](./媒体工具功能对齐检查报告_2026-09-02.md) §7.2.2）：
> **「我的知识库」≡「风格化管理」，二者是同一模块而非父子关系**。
> ① `my_knowledge_page.py` 文件头原文即「以「风格化」为核心的三区布局」；
> ② 页面 10 个按钮全部为风格化相关，无「新增/编辑条目」表单；
> ③ 数据层 `ENTRY_TYPES` 虽定义 8 类，但全仓库无页面引用，`add_item`/`update_item` 在 GUI 无调用点；
> ④ 三个消费页（`ai_script_page`/`product_script_page`/`storyboard_page`）只 import `STYLIZATION_TYPE`；
> ⑤ `import_kb_items`/`import_browser_samples` 只会产生 `REFERENCE_TYPE`，提炼只产生 `STYLIZATION_TYPE`。
> 故「风格化管理暂时不做」等价于「企业知识库整块暂缓」，剔除后无可移植的剩余范围。
>
> ❗ 若日后另做「通用知识条目 CRUD（品牌调性/话术风格/人设口吻/选题方向/禁用词）」，
> 属**原客户端不存在的新增功能**，需按新需求立项，不得算作移植对齐。

- 参照：my_knowledge_page.py（1166 行）三区布局 + `utils/my_knowledge_manager.py`（417 行）+ `core/knowledge_stats.py`（128 行）
- 数据层：MyKnowledgeManager —— **已核定（2026-09-02）**：纯本地 `data/my_knowledge.json`（`config.paths.MY_KNOWLEDGE_FILE`）+ `KNOWLEDGE_MATERIALS_DIR` 素材目录；服务端 openapi 无 my-knowledge / stylization 端点。**与 A2 的 `knowledge:*`（`a2-ipc.js` + `vector-store.js`，sqlite-vss 文档向量库）不是同一东西，不可混用。** 新端如恢复，走主进程 store 模式（参照 `creators-store.js`）。
- 落地要点（若日后恢复完整移植，约 40h）：
  - 风格化分组列表（`STYLE_DIMS`：账号风格/内容类型/产品品类/行业垂类）→ 画像详情 → 参考素材列表
  - 画像详情工具条：用此风格调文案 / 重新提炼 / 删除 / 加分（`like_item` +0.5，上限 10）/ 差评（`dislike_item` −0.3，下限 0）

### 4.3 产品文案创作（OtProductCopywriting）——媒体工具卡

- 参照：product_script_page.py
- 流程：产品选择（复用 fetchProducts）→ 展示性能/卖点（产品资料摘要）→ 可选风格化（知识库）→ 附加提示词 → 生成（LLM，走 `server.post('/llm/chat')` 或 agent 链路）→ 风格改写
- 落地要点：生成结果纯文本展示 + 复制；不落本地文件

### 4.4 分镜脚本创作（OtStoryboard）——媒体工具卡

- 参照：storyboard_page.py
- 服务端接口（已核实）：`GET /api/storyboard/scripts?topic=&page=&page_size=`（读）；保存脚本（写接口实现时以 openapi 核对）
- 流程：文案输入 → 生成分镜（每镜头：镜别/时长/音效/画面/旁白）→ 镜头引用素材（复用 fetchMaterials 语义搜索 + 即梦/联网素材）→ 保存（刷新工作台脚本列表）
- 落地要点：镜头列表竖向；引用素材复用 WbPickerDialog 骨架；即梦生成跳媒体工具素材生成（若已存在）或本地占位

> 原 4.4 飞书脚本创作（OtFeishuScript）已按 2026-08-30 裁决**移除，不移植**。

### 4.5 视频评价预测（OtVideoScore）—— ✅ 已实现（2026-09-02）

- 参照：hook_score_page.py
- 依赖：ffmpeg（已随包分发 resources/bin）+ 视觉模型
- 流程：选平台 → 上传视频（dialog.openFiles）→ 主进程 ffmpeg 抽关键帧 → 视觉模型预测（服务端 /llm/chat 带图或 /vision/*，实现时以 openapi 核对）→ 展示综合分+维度+建议 → 回填真实数据（本地持久化 video_prediction_manager 数据）
- 落地要点：ffmpeg 抽帧放主进程（montage 已示范 IPC）；预测结果展示卡
- **实现口径（已核定）**：
  - 抽帧：`main/ffmpeg-gate.js` 新增 `ffmpeg:extractFrames` IPC（返回 base64，`scale=512:-2 -q:v 4`），采样点与原码 `_sample_times` 逐行一致
  - 视觉调用：`POST /llm/chat/completions` 多模态 `messages`（`LLMAPI.ChatRequestMessage`），`temperature=0.4`，客户端固定 `model: ''`（视觉模型由服务端选择）
  - 分层：`composables/visionLogic.ts` + `videoScoreLogic.ts`（纯函数）/ `useVisionAnalyze.ts` + `useVideoScore.ts`（编排）/ `OtVideoScore.vue`（UI，SVG 雷达图复刻 `RadarChartWidget.paintEvent` 极坐标）
  - 持久化：`main/video-prediction-store.js` → `userData/video_predictions.json`，`prediction:list/add/setFeedback`；`calibration_text` 把历史「预测 vs 实际」回灌 prompt

### 4.6 视频营销检测（OtVideoMarketing）—— ✅ 已实现（2026-09-02）

- 参照：marketing_detect_page.py
- 依赖：ffmpeg + 视觉模型（与 4.5 共用关键帧抽取与视觉调用）
- 流程：上传视频 → 抽关键帧 → 研判（是否营销/品类/特征/建议）→ 展示
- 落地要点：与 4.5 共用「视频 → 关键帧 → 视觉模型」composable，避免重复
- **实现口径（已核定）**：`composables/videoMarketingLogic.ts` + `useVideoMarketing.ts` + `OtVideoMarketing.vue`；与 4.5 完全复用 `visionLogic.ts` / `useVisionAnalyze.ts` / `ffmpeg:extractFrames`，仅 `tag='marketing'`、采样函数（全片均匀 5~10 帧）与 prompt 不同；`temperature=0.3`；**不落库**（对照原版）

## 五、逻辑解耦约定（铁律）

| 文件 | 职责 |
|---|---|
| `views/OpsTools.vue` | 容器：卡片清单 + activeTool 切换 + 事件转发，仅绘制 |
| `components/ops-tools/Ot*.vue` | 各工具展示组件：只消费 composable 状态 + emit 事件 |
| `composables/opsTools*.ts` | 各工具业务逻辑：fetch、IPC、状态计算（服务端调用经 getTintin().server） |
| `services/`（如需要） | 跨工具共享：关键帧抽取、视觉模型调用、飞书同步 |

每个 composable 对应一个工具的完整业务；组件不得内嵌 URL/IPC 调用。
